# 按语义推进的分镜示例

本页演示 [visual-grammar](visual-grammar.md#semantic-beat-coverage) 的写法。下方是可放入 STORYBOARD.md 的单个 Frame 块，展示多句共用一个过程、结果停留阅读，以及与现有预演的衔接。它是规划示例；所列源码入口和 selector 是拟实现位置，没有对应的已制作音轨、素材、截图或通过结论。

正式项目沿用自己的 frame.md、输入 cue 和实际音轨；时间按 [input-contract](input-contract.md) 取得，素材按 [object-library](object-library.md) 就绪。例子的对象数量、分流条件和镜头选择随选题改变。

## Frame 1 — 按内容线索归档

- status: outline
- src: compositions/frames/f01-file-routing.html
- blueprint: compose
- rules: viewport-change
- 解释范围：文件按给定规则分流的知识示意，不代表某个产品的真实操作结果。
- 时间依据：下面四个来源 cue 的实际窗口；generated_voice 先取得 audio_meta.json，fixed 直接使用传入音轨和窗口。规划阶段用 cue 定位，取得音轨后在同一条目回填秒点与阅读窗。
- 风格依据：项目有效 frame.md；父片传入的完整风格按 upstream-frame 继承。

### 输入与观看过程

来源 cue：

| cue ID | 本例文案 |
| --- | --- |
| cue-001 | 整理要先找到文件里的线索。 |
| cue-002 | 金额归财务，会议归项目。 |
| cue-003 | 无法匹配的，先留给人确认。 |
| cue-004 | 所以，自动整理也要保留判断的边界。 |

本例使用三份自拟示意内容：doc-A 带“金额 500 元”，doc-B 带“会议纪要”，doc-C 只有“工作材料”。规则仅说明这些输入的归属：金额线索进财务区，会议线索进项目区，其余留在待确认区。

声音已经给出分类条件和待确认原则。画面补充每个结果来自哪份文件，以及未匹配内容如何被保留。先看同一批待整理文件，再靠近可读内容；把线索与原文件保持连接，随后连贯地交给三个归属区域，最后看清输出与原输入的对应。

### 语义覆盖与观察安排

| beat 与覆盖 cue | 主对象、可见事件或停顿 | 镜头、焦点与阅读 | 对象与来源 |
| --- | --- | --- | --- |
| b01：cue-001 | 从原内容提取两处线索；片段离开正文后仍与各自文件相连，doc-C 保持原内容。 | 从整组靠近内容区域，A 的金额、B 的会议线索成为可读焦点；原文件身份仍能追踪。 | doc-A、doc-B、doc-C 的内容来自本例自拟示意文案；线索与连接为语义图形，svg_role: companion。 |
| b02：cue-002、cue-003 | 同一批文件连续分流：A 进入财务区，B 进入项目区，C 留在待确认区。两句共同覆盖一个过程，C 的去处接在同次分流中。 | 跟随当前归属变化，交接时让来源、线索与去处可同时辨认；退开后恢复三者的整体关系。 | 沿用 b01 的对象身份；三个目标区是本题组织关系，svg_role: hero。 |
| b03：cue-004 | 保持 b02 已形成的结果，比较已归档与待确认部分，让观众理解判断边界。 | 保持清晰全貌和必要标签，给结果共同阅读窗口；“判断边界”的文字强调依本段职责和 motion-direction 编排。 | 复用既有对象与来源，不重建一组结果或重播分流。 |

本段强调“可匹配与待确认同时存在”的结果；接收上段已有文件集合时沿用其身份，向下段交出归属及待确认对象。若本段就是结尾，保留结果作为最终阅读态。

### 状态证据与实现位置

| 关键变化 | 计划核对的状态 | 拟实现位置 |
| --- | --- | --- |
| 内容线索被提取 | 提取前正文；片段离开但仍与来源相连的过程；线索与文件对应的结果 | #doc-A、#doc-B、#doc-C、.clue；时间线标签 extract-clues |
| 文件发生分流 | 待整理状态；来源、规则与去处仍能对应的交接过程；三个归属区结果 | .route、.destination；时间线标签 route-members |
| 结果比较与收束 | 共用上行结果态，核对清晰度、共同可见范围与 cue-004 的实际阅读窗 | #routing-world 与 .result-label；时间线标签 read-result |

这些位置在本 Frame 的 src 中实现并核实后，才可作为真实实现引用；截图和播放区间按实际输出回填以上条目。具体文件外观尚需按 object-library 检索、取得并登记；可控文字、连接与分类结构围绕选中素材实现。本例三路归属也不等同于 qualitative-set-filter 元数据限定的单条件两集合，组件选择仍按 component-contract。

### 预演与精修接续

本例尚无已审看的同类过程证据，拟验证线索提取后身份能否追踪、分流交接是否可见，以及两句共用动作后结果能否读完。按 [quality 的现有检查](quality.md#storyboard-keyframes)，用采用音轨预演 b01 至 b03 的完整过程；若已有覆盖这些风险的有效范例，就引用准确版本和区间并核对本段适配。

同一份草稿承担过程和适用的二维观察路线检查，使用拟交付的对象 ID、局部动作和 world 变换归属。先让完整观看过程成立，再精修次要材质与曲线；实际证据及结论写现有 ART-REVIEW。仅完成本页文字或分镜包，不完成关键帧、素材或动态验收。
